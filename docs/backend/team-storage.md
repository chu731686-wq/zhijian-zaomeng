# 小团队服务器存储与默认同步

## 数据位置

默认配置下，从 `app/` 启动后端：

- `app/data/infinite-canvas.db`：SQLite 数据库，保存账号、画布项目（节点、连线、视口、助手会话等）、素材清单和媒体索引。画布使用现有 `canvas_projects` 表；素材清单和删除记录保存在 `user_configs.asset_data`，媒体索引使用 `storage_objects`。没有新增数据库表。
- `app/data/uploads/<用户 ID>/<年>/<月>/<日>/`：上传或生成的图片、视频、音频。文件使用随机 ID 命名。默认服务器磁盘存储无需配置 S3 或 WebDAV。
- 浏览器 IndexedDB：未登录时的画布与素材，以及各账号独立的本机缓存。账号缓存按用户 ID 分区；退出登录恢复未登录时的本机数据，不把上一账号的画布或素材导入另一账号。

`DATABASE_DSN` 可以改变数据库位置，`UPLOAD_DIR` 可以改变媒体目录。Docker 默认对应 `/app/data/infinite-canvas.db`、`/app/data/uploads/`，需把 `/app/data` 挂载到持久卷。MySQL/PostgreSQL 仍使用配置的数据库。

服务器磁盘文件通过 `/api/files/<ID>/content` 读取，必须登录文件所属账号；知道文件 ID 也不能跨账号读取。浏览器通过登录后建立的 HttpOnly 文件会话 Cookie 加载图片、视频和音频，退出登录清除该 Cookie。视频和音频支持 HTTP Range 请求。`uploads` 目录不应配置成公开静态目录。

## 同步与导入

登录后的账号默认自动同步画布项目、节点、助手会话和素材清单；上传和生成的图片、视频、音频默认保存到服务器。未登录时上传文件和画布仍保存在本机。这里的自动同步固定开启，无需额外开关；模型接口和密钥存储方式沿用现有实现。

画布修改约 400 毫秒后保存，素材修改约 600 毫秒后同步。先传媒体文件，再保存引用文件的画布或素材，避免服务器清单引用另一个浏览器无法读取的 `blob:` URL 或本机存储键。相同账号内相同来源媒体复用上传结果。

首次登录检测服务器没有的本机画布与素材，弹窗显示“把本机的 N 个画布、M 个素材传到你的账号？”。选择“传”后，画布每批最多 10 个、素材每批最多 20 个，批内媒体依次上传，弹窗显示已完成条数。选择“先不传”会保留本机原始数据，以后在首页、画布列表或编辑器的账户菜单选择“上传本机画布和素材”再次导入。导入失败后重试，会重新查询服务器，跳过已完成的记录。

同 ID 画布或素材按 `updatedAt` 选择最近修改的版本；并行修改不同素材会合并保留，删除记录防止其他浏览器旧缓存把素材复活。请保持各电脑时间准确。画布删除仍使用现有服务器软删除机制，本机删除 ID 会保留并在重试同步时再次发送。同步失败显示提示，本机缓存保留，恢复联网或刷新后重试。另一台电脑重新登录或刷新时加载最新服务器数据，不提供实时协同编辑。

S3/R2/WebDAV 仍可通过现有管理员或用户存储配置选用；没有可用云存储配置时使用服务器磁盘。已写入磁盘的文件继续通过磁盘读取，不要求当前仍选择磁盘存储。外部存储的访问方式和公开地址行为沿用原配置。

删除素材清单不会立即清除服务器媒体，避免其他画布或另一台电脑仍在引用的文件被误删；本卡未新增服务器孤立文件清理界面。

## 备份与恢复

默认 SQLite 部署备份整个 **`app/data/` 文件夹**，其中数据库和 `uploads/` 缺一不可。Docker 复制 `/app/data` 对应的宿主机挂载目录或备份整个数据卷。

1. 暂停后端服务，让正在进行的上传和数据库写入结束。
2. 完整复制 `app/data/`，保留目录和文件权限。目录中若有 SQLite `-wal`、`-shm` 文件一并复制。
3. 重新启动后端。

恢复时停止服务，把同一份备份的数据库和上传目录一起放回原位置，再启动服务。改变过 `UPLOAD_DIR` 或 `DATABASE_DSN` 时，需要分别备份它们实际指向的目录和数据库。MySQL/PostgreSQL 使用数据库自身的备份工具，同时备份上传目录；S3/R2/WebDAV 文件还需在对应存储端备份。没有上传到账号的本机数据只在原浏览器中，需先导入或使用现有导出功能另存。

## 换浏览器验收

所有浏览器应打开同一部署地址，前端 `/api/` 转发到同一个后端。

1. A 浏览器登录账号甲，打开 `/canvas` 新建画布，命名“跨电脑验证”，添加文本和一张上传图片；打开助手会话写入一条消息，再到 `/assets` 添加一项素材。也可增加视频、音频。等待几秒，确认没有同步失败提示。
2. B 浏览器使用独立配置文件或另一台电脑，打开同一地址，登录账号甲。打开 `/canvas`，应看到“跨电脑验证”，节点、图片和助手会话都在；打开 `/assets`，应看到素材，图片可显示，视频/音频可播放。刷新后仍应存在。
3. 复制图片的 `/api/files/<ID>/content` 地址，在未登录的独立浏览器或登录账号乙的浏览器打开，应返回 403；账号甲直接打开应能显示图片。
4. 退出账号甲，未登录创建一个本机画布和素材，再首次登录另一测试账号，确认弹窗数量准确。选“先不传”，B 浏览器登录该账号应看不到这批本机数据；A 的账户菜单再次导入后，B 刷新应能看到，图片也能显示。
5. A、B 分别修改不同素材，刷新后两项修改都保留；对同一素材或画布先后修改，保留最近修改版本。删除素材后，另一浏览器的旧缓存不应重新上传它。断网修改后恢复网络，确认可重试同步。

本次开发环境已通过任务卡的 Go 构建与 TypeScript 检查，以及现有存储接口测试；内存模拟覆盖媒体引用转换、助手图片、重复上传去重和用户文本保持原样。开发沙箱禁止监听 TCP 端口，以上真实双浏览器步骤需在运行环境执行。
